# B站评论区图片批量下载（油猴脚本）

批量下载 B 站视频评论区用户图片的 Tampermonkey / Violentmonkey 用户脚本。

某条评论有 **9 张图、页面却只显示 8 张** 时，第 9 张需要点开图片查看器翻页才能看到；本脚本能完整识别这类被折叠的图片，并支持批量下载**原图**。

## 特性

- **接口直取，图片最全**：hook 页面自身的 `fetch` / `XMLHttpRequest`，直接从评论接口 `content.pictures` 读取全部图片（含 UI 不渲染的第 9 张）；另有 wbi 签名接口与旧接口兜底。
- **只收评论图**：通过「可信来源闸门 + new_dyn/album 白名单 + 尺寸判据」多层过滤，视频封面、小黄脸表情、头像、图标、其它视频的图一律不收。
- **隐藏图识别**：4 条互相独立的检测路径（接口、查看器组件 props、查看器 DOM/懒加载、按 rpid 精确补全），任意一条命中即可拿到隐藏图。
- **原图下载**：利用 B 站 CDN 的 `@宽w_高h` 参数请求原始尺寸，支持三档画质。
- **灵活命名**：默认使用 B 站原文件名，支持 `{author}` `{rpid}` `{i}` 等占位符模板；同名冲突自动加短 hash。
- **新评论区兼容**：支持新版评论区的 Shadow DOM 深度遍历。
- **自检完备**：内置 226 项断言的自检脚本。

## 安装

1. 浏览器安装 Tampermonkey（推荐）或 Violentmonkey。
2. 打开 Tampermonkey 面板 →「添加新脚本」，把 `bili-comment-images.user.js` 的内容粘贴进去保存；或直接把 `bili-comment-images.user.js` 文件拖进浏览器窗口。
3. 确认脚本权限：
   - `GM_xmlhttpRequest`（跨域请求，脚本已声明 `@connect`）；
   - 首次点下载时浏览器/扩展会询问「是否允许下载多个文件」，务必选择**允许**，否则只会存下第一张。
4. 打开视频页（`https://www.bilibili.com/video/BV...`），右下角出现粉色面板；`Alt+B` 或面板右上角 ▾ / ✕ 可折叠（不会记忆隐藏状态，刷新后必定重新出现）。

## 使用

1. 打开视频页面，脚本会在约 2.5 秒后自动调接口拉取全部评论图片；也可手动点面板上的 **「① 抓取评论区（推荐）」**。
2. 在面板中核对张数（每条评论显示「9 张 完整」或「已抓 8 / 应有 9，差 1 张」）。
3. 勾选要下载的图片，点 **「⬇ 下载选中」**。

更多控制：

- **扫描当前页面**：只从已加载的评论 DOM 中抓取（不调接口，只认单条评论容器内的图）。
- **抓查看器**：先点开图片查看器、翻到隐藏图，再点该按钮。
- **补全缺图**：对张数不足的评论按 `rpid` 再请求一次接口补齐。
- **清掉多余图**：删除不像评论图的记录。
- 每个缩略图可点击切换勾选；「全选 / 全不选」「复制链接」「下载本条」即时生效。

## 只采集「评论区用户上传的图片」

脚本只认评论里用户上传的图，不会混入视频封面、表情、头像、图标或页面上其它视频的图。核心是**可信来源闸门**：

> 只有接口确认过的评论（评论 `rpid` 或评论者 `mid`）名下的图片才会被采纳；其它来源（DOM 扫描 / 图片查看器 / 页面缓存）的图必须能对上其中之一才收，否则丢弃。

分层判定：

1. **接口层（唯一权威）**：只取评论 `content.pictures`，只接受 `/bfs/new_dyn/`、`/bfs/album/` 命名空间，排除 `/bfs/face/`、`/bfs/emote/`、`/bfs/vip/`、`/bfs/garb/`、`/bfs/live/`、`activity-plat` 等。
2. **DOM 层（补充）**：图片必须在**单条评论容器**内（`bili-comments` 整个外壳不算），且容器上的 `data-rpid` / 评论者 `mid` 必须是接口确认过的。
3. **查看器层（补充）**：只在图片查看器真的打开时扫描，同样要求能对上可信评论。
4. **表情排除**：带 `emote` 类名/属性、`alt` 含「表情」、宽度 ≤ 40px 的小图跳过；文件名含 `emote` / `emoji` / `sticker` 等标记的也跳过。
5. **尺寸硬判据**：用户上传的评论图尺寸在 1000px 量级（例如 1066×1600），小黄脸表情只有几十~200px：
   - 任何宽高都 ≤ 200px 的图直接判为表情丢弃（哪怕地址是正经的 `/bfs/new_dyn/`）；
   - 接口返回的图片若 `top_right_icon` 指向表情资源，也丢弃；
   - 一整组（≥4 张）全是同样尺寸的小图 → 判定为表情包，整组丢弃。

> 事实依据：B 站小黄脸表情在接口中是独立的 `content.emote` 对象（`/bfs/emote/` 域名），并不走 `content.pictures`；因此接口一路本身是干净的，小黄脸只会从 DOM / 查看器一路混进来——尺寸判据正是为它准备的。

被丢弃的数量会显示在面板统计里（「已过滤：可疑图 N + 表情 M」）；控制台也会打印前 3 个被忽略的地址，方便确认过滤是否生效。

> 关键前提：先让接口抓一次（点「① 抓取评论区」或等自动抓取），接口成功后可信评论身份才建立，DOM / 查看器补充的图才有判断依据。

## 为什么能识别隐藏的第 9 张

1. **接口数据（主力）**：B 站评论接口 `content.pictures` 返回了全部图片，只是前端只渲染前 8 张。脚本 hook 页面自身的 `fetch` / `XMLHttpRequest`（注入 main world），拿到完整数组；另外也会主动请求 `/x/v2/reply/wbi/main`（wbi 签名）、`/x/v2/reply`、`/x/v2/reply/reply` 作为兜底。
2. **查看器组件内部数据**：深度遍历所有 Shadow DOM，读取挂载了图片数组的组件属性（`pictures` / `allPictures` / `list` / `imgList` 等）。
3. **查看器 DOM + 懒加载属性**：递归遍历（含 open shadow root）所有 `img` 的 `data-src` / `src` / `srcset` / `currentSrc`，并用 `PerformanceObserver` 嗅探查看器翻页时的新图片请求。
4. **按 rpid 精确补全**：对已识别 `rpid` 但张数不足的评论，用它自己的 `rpid` 再请求一次接口，一次性补齐。

**张数校验**：脚本对比「该评论应有的总数」与「实际抓到的数量」，面板显示 `9 张 完整` 或 `已抓 8 / 应有 9，差 1 张`，不会假装抓全。

## 画质说明

B 站 CDN 支持在图片地址后追加 `@` 格式化参数。面板「画质」三档：

| 档位 | 实际请求 | 说明 |
| --- | --- | --- |
| 原图尺寸（默认） | `原地址@1066w_1600h_1e_1c.jpg` | 按接口给出的真实宽高请求，让 CDN 吐出原始尺寸 |
| 原图 + 无损优先 | `原地址@1066w_1600h_1e_100q.png` | 叠加 `100q` + png，尽量避开二次压缩，体积最大 |
| 接口原样 | 原地址 | 接口给的地址（通常是压缩缩略图），体积最小、速度最快 |

> 接口返回的 `img_width` / `img_height` 就是原始像素尺寸；GIF 动图会被标记，建议用「接口原样」档下载以免被转码。

## 命名规则与保存位置

默认使用 B 站原文件名：`74d196ecebf20141180f5b8dbe08ad42345177276.jpg`（`new_dyn` 的 hash 名，便于溯源且不会因昵称相同而互相覆盖）。

- 命名框默认值为 `{name}.{ext}`，可改成任意模板；改乱了点「用原文件名」一键恢复。
- 同名冲突自动在原名后加一段短 hash，不会互相覆盖，也不会被浏览器改成 `(1)` `(2)`。
- 自动清理 Windows 非法字符（`\ / : * ? " < > |`）、保留名、超长名，并防止 `../` 目录穿越。
- 勾选「按作者建子文件夹」保存为 `作者名/文件名`。
- 下载目录由浏览器默认下载目录决定。

可用占位符：

| 占位符 | 含义 |
| --- | --- |
| `{name}` | 图片原文件名（不含扩展名） |
| `{ext}` | 扩展名（模板里写了 `{ext}` 就不会再自动追加） |
| `{i}` | 该评论内的图片序号（两位补零） |
| `{n}` | 该评论图片总数 |
| `{author}` | 评论作者昵称 |
| `{rpid}` | 评论 ID |
| `{mid}` | 作者 UID |

示例：`{rpid}/{name}.{ext}`。

## 常见问题

**面板没出现 / 没有图片**
确认脚本已启用、页面是 `www.bilibili.com/video/...`；刷新一次页面或按 `Alt+B`。B 站是单页应用，切换视频后脚本会自动清空重抓。

**面板在某个浏览器里不显示**
先按 `Alt+B`（可能只是被折叠）。脚本不依赖 `inset` 简写（Chrome < 87 不支持）；面板建好后在 1.2s / 4s 各做一次可见性自检，若宿主不在 DOM、量不到尺寸或被拖出视口，会自动切换为 light DOM 兼容模式并抬高 z-index。仍看不到时打开 F12 控制台，把 `[B站评论图]` 开头的日志贴进 issue 即可定位。

**抓到了小黄脸表情**
见「只采集评论区用户上传的图片」一节，面板统计会显示「已过滤：可疑图 N + 表情 M」。若仍有漏网，打开 F12 控制台，把被忽略图片的 URL 和尺寸贴进 issue 即可。

**「仍有 N 张未抓到」**
点「补全缺图」或该评论右侧的「补全」。若仍失败，说明接口对该评论有风控（可能返回 `-352`），先在页面上手动翻到那几条评论，再点「扫描当前页面」/「抓查看器」。

**只下下来一张**
Tampermonkey 首次批量下载会询问授权，被拒绝后剩余图片会被静默拦掉；在扩展设置里允许该脚本的多文件下载即可。

**接口返回 `-352` / 空数据**
B 站风控，脚本会自动降级到旧接口；登录状态下成功率更高。

**隐私**
所有解析和请求都在本地浏览器中完成，脚本不上报任何数据。
